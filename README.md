# 聚光壁纸 · Spotlight Wallpaper

> 鼠标指向哪里，哪里就"透出"另一幅画。光斑之内一幅图，光斑之外另一幅图。

三个入口，各司其职：

| 入口 | 文件 | 说明 |
| --- | --- | --- |
| **一键启动**（推荐） | `启动聚光壁纸.bat` | 双击这一个就够了：壁纸没开就拉起，面板没开就打开；**已经在跑的不会被重启**，开着的面板会被抬到前台 |
| **控制面板** | `open-panel.bat` | 只开面板（壁纸在跑就复用，不在跑会由面板拉起）。图形界面：选图、拖滑块、实时预览、看日志 |
| **桌面版（真正的壁纸）** | `wallpaper.pyw` / `start-wallpaper.bat` | 只起壁纸。挂进 Windows 桌面层，待在桌面图标**下面**。图标照常显示、照常双击，不挡任何操作 |
| **网页版（零依赖）** | `index.html` | 双击即可看效果，不需要 Python；也可交给 Lively Wallpaper / Wallpaper Engine 当动态壁纸 |
| **单文件 exe**（可选） | `SpotlightWallpaper.exe` | 打包产物：一个 exe 搞定，目标机器不用装 Python。一条命令自己出包，见 [十一、打包成单个 exe](#十一打包成单个-exe) |

### 开机自启（可选）

双击 **`安装开机自启.bat`** —— 它往启动文件夹（`shell:startup`）放一个快捷方式，
指向 `launch.pyw --no-panel`：**开机只挂壁纸，不弹面板**（桌面归壁纸，面板随时
`Ctrl+Alt+P` 叫回来）。取消就双击 `移除开机自启.bat`，或在任务管理器 → 启动应用里关掉。

为什么这样设计：登录后弹一个调参窗口在脸上不是你想要的；壁纸是"背景"，应该安静地就位。
想换图片、调效果，双击 `启动聚光壁纸.bat`（已开着的壁纸不会被动，只把面板叫出来）。

两个启动脚本的幂等性说明：**重复双击没有副作用** —— 壁纸用单实例互斥量判重（跟着进程
生命周期走，强杀也不留鬼影），面板用 pid 文件 + 存活校验判重（过期文件自动清掉再拉新的）。

## 一、控制面板：怎么用

### 打开

双击 **`启动聚光壁纸.bat`**（壁纸 + 面板一起就位），或只开面板用 **`open-panel.bat`**。

会弹出一个**无边框窗口**（本质是 Edge 的"应用模式"，看起来就是个独立小软件），左边是参数，右边是实时预览和日志。

> 面板是"遥控器"，壁纸是另一个独立进程 —— 所以**退出面板 ≠ 停壁纸**。但这个规则不用猜也不用记：现在每次退出面板都会**先问你一句**（见下），也可以让它记住你的选择不再问。

### 退出面板：每次都会先问你（规则 A）

三个退出入口 —— 顶栏 `退出面板` 按钮、托盘菜单 `退出面板`、标题栏 `×` —— 行为**完全一致**：先弹一个原生对话框三选一，

1. **只退面板**（壁纸继续跑）
2. **连壁纸一起停**（桌面恢复成系统壁纸）
3. **取消**

勾选对话框里的 **「不再询问，以后都这样做」** 后，你的选择会写进配置（`panel_exit_action`），之后三个入口都不再弹框、直接照办。想改回来：把项目目录 `wallpaper-config.json` 里的 `panel_exit_action` 改回 `"ask"`。面板上的 `恢复默认效果` 只重置滑块，**不会**弄丢这个记忆（图片路径和面板设置同样不动）。

### 在系统设置里换了壁纸？（规则 B）

本程序**从不修改系统壁纸**，只是把一张整屏窗口**盖**在桌面上面。所以在「设置 → 个性化 → 背景」里换壁纸，屏幕上**不会有任何变化** —— 不是设置坏了，是你换的那张正被盖着。

这时面板顶部会出现一行提示：`系统壁纸已改为 xxx —— 本程序正盖着它`，附两个按钮：

- **`停止壁纸，显示系统壁纸`** —— 停掉本程序，立刻看到你在设置里换的那张；
- **`知道了`** —— 收起提示，什么都不改。

只提示、不自动停：想让屏幕变成哪张，由你点按钮决定。壁纸进程按约 1.5 秒一次的频率（独立节流，不占渲染帧）检查系统壁纸路径；如果用的是幻灯片 / Windows 聚焦这类会自己频繁换图的动态壁纸，程序会判定为"它自己在动"而**不弹提示**，避免刷屏误报。

### 界面速览

| 区域 | 内容 |
| --- | --- |
| 顶栏 | 状态灯（壁纸在跑 / 已挂桌面层 / CPU 占用）、四套主题切换、`最小化到托盘`、`退出面板` |
| 图片 | 两行：**光斑外**（平时桌面看到的那张）、**光斑内**（鼠标附近透出来的那张）。各带缩略图、文件名、当前路径，和一个 `选择…` 按钮（系统原生选图框）。卡片右上角另有 `重新读取` |
| 效果 | `光斑大小` `边缘柔和` `暖光强度` `跟随速度` `刷新上限` 五个滑块 |
| 开关 | `静止游走` `离开桌面时冻住光斑` `日志记帧率` 三个开关 |
| 操作 | `启动/停止壁纸`（按当前状态变）、`重启`、`恢复默认效果`、`打开文件夹` |
| 实时预览 | 跟着鼠标位置**真正的渲染结果**（不是示意图），可以把光斑**拖着走** |
| 诊断日志 | `wallpaper.log` 尾部，按等级上色；带 `打开文件` `刷新` |

**换图最顺手的做法**：直接把图片**拖到窗口里**那一行上松手 —— 拖到"光斑外"那行就是换外层，拖到"光斑内"那行就是换内层。比"点按钮、再在对话框里翻文件夹"快得多。上传的图会自动压到最长边 2560px 再存。

### 收进托盘

托盘（任务栏右下角那个小箭头里）会有一个**金色光点图标**——面板关着的时候也认得出是它。

| 操作 | 效果 |
| --- | --- |
| 点标题栏的**最小化** | 面板收进托盘（任务栏按钮消失） |
| 顶栏 `最小化到托盘` | 同上 |
| **单击**托盘图标 | 收起 / 显示，来回切 |
| **右键**托盘图标 | `显示面板` / `收起面板`、`重启壁纸`、`退出面板` |

适用场景：调完参数想让它待在旁边，又不想占任务栏一格。

> **托盘图标装不上时，`最小化到托盘` 会变成灰的（停用）。** 这不是 bug，是故意的：
> 托盘图标是唯一能把面板捞回来的入口，入口不存在还把窗口藏起来，你就只剩任务管理器一条路了。
> 悬停能看到具体原因（比如通知区域被系统策略关掉了）。

### 滑块的三种输入方式

别用鼠标硬拖了，这个面板有更准的办法：

| 操作 | 效果 |
| --- | --- |
| 拖动 | 常规拖拽 |
| `←` `→` | 精确 ±1 |
| `Shift` + `←` `→` | 步进 ±10 |
| `Home` / `End` | 直接跳到最小 / 最大 |
| **双击滑块** | 恢复该项默认值 |
| **点右侧数字** | 变成输入框，直接敲精确数值，回车生效 |

每一次改动都会**自动写进 `wallpaper-config.json`**，壁纸进程在 1 秒内跟上 —— 不用重启，不用手改文件。

### 主题

顶栏的四套主题：`暗夜` `紫罗兰` `墨黑` `明亮`，选择记在本地，下次打开还是它。

### 它改的就是这些参数

面板滑块 ↔ `wallpaper-config.json` 一一对应，等于把下面第四章的表格做成了可视化：

`size` `feather` `glow` `follow` `fps` `drift` `pause_when_covered` `verbose`

> 面板和配置文件是**同一个真相**：面板写完，文件立刻变；你手改文件，面板 2 秒内也会刷新过来。

## 二、桌面版：怎么用

### 启动

| 想做什么 | 双击这个文件 |
| --- | --- |
| **当壁纸用** | `start-wallpaper.bat` |
| **安全预览**（开个小窗口，绝不会遮挡全屏） | `preview-window.bat` |
| **控制面板**（图形化调参） | `open-panel.bat` |
| **停止壁纸** | `stop-wallpaper.bat` |

> 也可以直接双击 `wallpaper.pyw`，效果同「当壁纸用」。

### 退出

**任何模式下都能退出**，三条路随便挑一条：

| 方式 | 说明 |
| --- | --- |
| `Ctrl` + `Alt` + `Q` | **全局热键**，不占用焦点，任何时候都能按 —— 记不住别的就记这个 |
| 窗口的 `×` 按钮 | 安全预览模式下直接点标题栏右上角 |
| `Esc` | 安全预览 / 全屏预览下有效 |
| `stop-wallpaper.bat` | 万一程序卡住，双击它 |

### 三种模式的区别

| 参数 | 模式 | 会不会遮挡屏幕 |
| --- | --- | --- |
| 无参数（默认） | 挂进桌面层，当壁纸 | 不会。它待在图标下面 |
| `--window` | 1200×720 普通窗口，有标题栏 | 不会。就是个普通小窗口 |
| `--full` | 全屏，但**不置顶** | 不会。你点别的窗口，它自动让开 |
| `--selftest` | 只做结构自检并打印结果，不留窗口 | 不会 |

桌面层挂载失败时（不同 Windows 版本差异较大），程序会**自动降级成安全小窗口**并在日志里写清原因 —— 绝不会留下一个盖住全屏的窗口。

## 三、换自己的两张图

**四条路，随便挑一条。换完立刻生效，不用重启程序。**

### 路 1（最直观）：拖进控制面板

双击 `open-panel.bat` → 把图片**拖到窗口里的对应行**上松手。或点 `选择…` 走系统原生选图框。

### 路 2：全局热键 + 选图对话框

| 热键 | 作用 |
| --- | --- |
| `Ctrl` + `Alt` + `1` | 选**光斑外**的图 —— 平时桌面看到的那张 |
| `Ctrl` + `Alt` + `2` | 选**光斑内**的图 —— 鼠标附近透出来的那张 |
| `Ctrl` + `Alt` + `R` | 重新读取图片（刚往 `images/` 里放了新图时用） |

选完会**自动记住**（写进 `wallpaper-config.json`），下次开机还是它。用的是系统原生选图框，不占焦点、不会被壁纸挡住。

### 路 3：往 `images/` 目录丢文件

按下面的名字命名，再按一次 `Ctrl` + `Alt` + `R`：

```
images/out.jpg      ← 光斑【外】显示的图（也就是平时的桌面背景）
images/in.jpg       ← 光斑【内】显示的图
```

也认 `out.png` / `out.webp` / `out.jpeg` / `out.bmp`，外层同理写 `outer.*`，内层 `inner.*`。

### 路 4：直接写路径

编辑 `wallpaper-config.json` 里的 `"outer"` 和 `"inner"`，填绝对路径即可，存盘后 1 秒内自动生效。

> **优先级**：选过的绝对路径 > `images/` 目录约定 > 内置渐变占位图。
> 想退回路 3，把配置里那两行路径改回 `images/out.jpg` 即可。

### 关于图片

仓库里**不附带**任何图片（`images/` 只有一个说明文件），需要你自己放两张。没有图也能跑 ——
程序会先用内置的渐变占位图把界面铺起来，放好图再刷新即可。

想快速看效果，可以用系统自带壁纸凑一对：`Windows\Web\Wallpaper\ThemeC\img28.jpg`（白天）和
`img30.jpg`（黄昏）是同一机位的湖景，一明一暗，光斑扫过去像"天色变了"。想换成自己的，上面四条路随便走。

### 两张图怎么配更好看

- **构图对位**：同一机位、同一视角，鼠标移过去像"世界翻了个面"，最震撼。
- **明暗反差**：一亮一暗、一暖一冷，光斑边界自然成为视觉焦点。
- **分辨率**：≥ 2560×1600 更稳（高分屏下光斑边缘更细腻）。更大的图会自动预缩，不会白占内存。
- 想做成「放大镜 / 水晶球」的感觉：把 `feather` 调到 5–10，`size` 调到 800 左右。

## 四、调参数

**首选控制面板**（见第一章）。想手改或写脚本，编辑 `wallpaper-config.json`（首次运行自动生成）：

| 键 | 含义 | 默认 | 建议 |
| --- | --- | --- | --- |
| `outer` | 光斑**外**的图路径 | `images/out.jpg` | 相对路径按本目录解析 |
| `inner` | 光斑**内**的图路径 | `images/in.jpg` | 同上 |
| `rev` | 图片版本号，加 1 强制重读图片 | 0 | 面板改图时自动加，一般不用管 |
| `size` | 光斑基准尺寸（圆形时即直径，单位物理像素） | 380 | 380–560 有"探照灯"感；800+ 是"水晶球" |
| `feather` | 边缘柔和 0–100 | 45 | 写真 45–70；插画/图标 5–20 |
| `glow` | 光斑内的暖色柔光强度 0–100 | 25 | 20–40，太亮会发灰 |
| `follow` | 光斑追赶鼠标的快慢 | 0.45 | 0.06–0.12 有拖尾、像在水中；0.35+ 跟手 |
| `drift` | 鼠标静止 3 秒后光斑自己缓慢游走 | `false` | 好看，但**会一直重绘**（约 30% 单核），笔记本慎开 |
| `fps` | 刷新上限 | 60 | 40 已经足够顺；60 更跟手也更费电 |
| `pause_when_covered` | 光标不在桌面上时**冻住光斑**（不跟随、不重绘） | `true` | 强烈建议保持 `true`，这是最省 CPU 的一项。关掉则照常跟着光标走 |
| `verbose` | 每 5 秒往日志写一次实测帧率 | `false` | 排查卡顿时临时改成 `true` |

> 屏幕如果是 2560×1600（比 1080p 大一倍多），`size` 建议比 1080p 时再大一些。

## 七、性能

### 网页版

踩过的坑：**别给全屏图层做逐帧遮罩**，那会让重绘面积等于整屏。

| 分辨率 | 整屏遮罩（初版） | 小窗口 + GPU 位移（现在） |
| --- | --- | --- |
| 1920×1080 | 126 fps | 165 fps |
| 2560×1440 | 42 fps | 165 fps |
| 3840×2160 | 22 fps | 165 fps |

### 桌面版（本机实测：Intel UHD 核显 / 2560×1600 @150%）

| 指标 | 优化前 | 现在 |
| --- | --- | --- |
| 主循环 | 32 Hz | **52 Hz**（上限 60） |
| 单次渲染耗时 | 5.40 ms | **2.84 ms** |
| CPU（光标在桌面、持续跟随） | 30.7% | **14.8%** |
| CPU（光标在别的窗口上） | 30.7% | **1.4%** |
| CPU（什么都不动） | 30%+ | **≈0** |

四个关键点：

1. **主循环为什么只有 32Hz**：Windows 默认定时器精度是 15.6 ms，请求 16 ms 的定时器总会错过第一个 tick、落到第二个，于是恒定输出 32 Hz —— 比设定值差一半。启动时把定时器精度提到 1 ms 就正常了（退出时归还）。
2. **光斑图不要每帧新建**：每帧新建 `PhotoImage` 要 3.3 ms，改成建一次、之后原地更新只要 2.2 ms。光晕的内容根本不变，连更新都省了，只挪位置。
3. **鼠标底下被别的窗口压住就不画**：光斑永远跟着鼠标，鼠标在 IDE / 浏览器里时它压根看不见。实测这一条把后台占用从 30% 压到 1.4%。切回桌面自动恢复。
4. **静止时放慢轮询**：没有东西要画时轮询周期自动拉到 40 ms。

另外还有常驻看护：换分辨率、explorer 重启导致壁纸掉了，会自动重新挂载。

### 控制面板

面板是**按需渲染**：只有你动滑块 / 拖预览时才重新算预览图，没交互时 2 秒一次轻量状态轮询，CPU 基本为零。预览用的是**和壁纸完全同一条渲染管线**（同一份 `compose_preview` 代码），所以你在面板里看到的边缘柔和度，就是桌面上的真实效果。

预览本身也做过优化：光斑羽化遮罩和暖光的小图核心被缓存起来，改尺寸时只重做放大那一趟。本机实测拖光斑约 213 fps、拖羽化+暖光约 60 fps。

## 八、出问题看这里

### 日志

`wallpaper.log` 记录了每一次启动、挂载结果和异常。**控制面板的「诊断日志」看的就是它**；面板自己写进去的条目带 `面板 ` 前缀，一眼能分开。

| 日志 | 含义 |
| --- | --- |
| `桌面层方案：宿主=… 分层子窗口=True` | 认出了新版 Windows 的桌面结构，走分层方案 |
| `挂载校验通过：桌面层（Progman 的分层子窗口，在图标层下面）` | 结构上挂对了 |
| `循环 …Hz｜渲染 …帧/秒` | 只有 `verbose: true` 时才有，用来看是不是在空转 |
| `z 序校验未通过，降级为小窗口预览` | 这个系统结构不支持，已自动降级，不会挡屏 |
| `看护：重挂成功` | 分辨率变化 / explorer 重启后自动恢复 |
| `面板 控制面板：光圈=… 柔和=…` | 面板的改动已被壁纸接收 |
| `面板 图片已更新` | 面板换了图（`rev` 变了），壁纸重新读了文件 |

### 光斑不动了 / 桌面上有块方块

| 症状 | 原因与处理 |
| --- | --- |
| 光标移到窗口或任务栏上之后，光斑停在原地不跟了 | **这是故意的**（`pause_when_covered`）。光标底下不是桌面时，光斑冻在原地、一帧都不重绘 —— 最省 CPU，桌面露着的那部分也不会被动。想让它一直跟着光标走，把面板里那个开关关掉 |
| 桌面上出现一块**方块**，里面的画面和周围对不上 | 老版本 `_park()` 留下的 bug（只挪位置、不重画像素），已修。复验：`python _probe_covered.py`（壁纸要开着） |
| 从窗口回到桌面时，光斑"啪"一下就到新位置了 | 正常。冻结期间不重绘，回到桌面的第一帧才把它画到新位置 |

### 面板打不开 / 界面空白

| 症状 | 处理 |
| --- | --- |
| 双击 `open-panel.bat` 没反应 | 确认装了 Python，且 `open-panel.bat` 里的解释器路径对得上。装好 Python 后一般不用改 |
| 没弹出应用窗口 | 面板会依次尝试 Edge、Chrome；都不在时会打印一个 `http://127.0.0.1:端口` 地址，用任何浏览器打开它就行 |
| 界面能开、但预览是灰的 | 壁纸没在运行。面板「操作」区点 `启动壁纸` |
| 状态显示"没挂上桌面层" | 桌面层没挂上，壁纸降级成了小窗口。看 `wallpaper.log` 里那条降级原因 |
| 改了参数桌面没变化 | 面板和壁纸共用 `wallpaper-config.json`，先看面板状态灯是不是"已挂桌面层"；不确定就点 `重启` |
| 点一下开关/按钮，**整个界面（连标题栏）往上窜一截** | 老版本 `.sw` 没有 `position:relative`，里面绝对定位的隐藏 checkbox 逃出裁剪、把文档顶高了 397px，点它时浏览器把焦点元素滚进视野所致，已修。复验：`python _probe_switch.py`（见不变量 4） |

> 面板的服务**只绑 `127.0.0.1`**，外网访问不到，也没有任何第三方依赖 —— 用的是 Python 自带的 `http.server`。

### 托盘相关

| 症状 | 处理 |
| --- | --- |
| `最小化到托盘` 按钮是灰的 | 托盘图标没装上（通知区域被系统策略关了之类）。悬停看 `title` 里的原因。**这是故意的**：没图标却把窗口藏起来，你就找不回面板了 |
| 任务栏右下角找不到图标 | Win11 默认把新图标收进「^」小箭头里，点开找找；也可以拖到外面常驻 |
| 托盘图标点了没反应 | 面板进程可能已经退出了（此时图标本该消失）。看 `wallpaper.log` 最后一行是不是「面板已退出」；是的话重开一次面板 |
| 托盘菜单 `退出面板` 有效吗 | 有效，而且和按钮、标题栏 `×` 一样会**先弹三选一**（只退面板 / 连壁纸一起停 / 取消），见「规则 A」。勾了「不再询问」后则按记住的选择直接执行 |
| 通知区域留了个点不动的死图标 | 面板被强杀（任务管理器结束进程）时会这样，鼠标划过去它就消失了。正常退出（× / 托盘菜单）一定会摘掉图标 |

### 关于 Windows 11 24H2 及更高版本（本机是 build 26200）

微软改了桌面背景的渲染方式，这解释了一类"**结构全对、屏幕上啥都没有**"的怪现象：

- `Progman` 现在带 `WS_EX_NOREDIRECTIONBITMAP` —— 它自己**没有 GDI 内容**；
- 图标层 `SHELLDLL_DefView` 变成了 `WS_EX_LAYERED` 分层窗口；
- 壁纸由 `Progman` 下一个 z 序更低的 `WorkerW` 子窗口绘制。

后果：挂在 `Progman` 下的**普通**（非分层）子窗口，DWM 根本不会合成它。程序现在的做法是官方推荐的那套 —— 自己建一个 `WS_EX_LAYERED` 子窗口，z 序插在 `DefView` 之下、`WorkerW` 之上，并调 `SetLayeredWindowAttributes(alpha=0xFF)` 设成不透明。

**注意**：只加 `WS_EX_LAYERED` 而忘了设 alpha，窗口会是全透明的，症状和没挂载一样。这一步不能省。

## 十、给开发者：控制面板的接口

面板前端和后端之间就是一个本地 JSON HTTP 接口，想自己写前端 / 接别的工具都可以直接用。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/ping` | 存活探测，返回端口与打开方式 |
| GET | `/api/state` | **全量状态**：配置、`defaults`、取值上下限、屏幕尺寸、两侧图片信息、壁纸进程状态（活着 / 已挂桌面层 / CPU 占用 / 桌面层 z 序）、托盘状态（`active` / `hidden` / `hwnd` / `error`） |
| GET | `/api/zoom` | 预览视口几何（把屏幕坐标换算成预览里的位置） |
| GET | `/api/thumb?side=` | 某一侧的缩略图 |
| GET | `/api/preview?…` | 按当前参数渲染一帧预览（PNG，无损） |
| GET | `/api/log` | `wallpaper.log` 的尾部 |
| POST | `/api/config` | 写入配置（服务端会**夹取越界值**，并且永远基于磁盘上的当前值构造，不会覆盖你没提到的字段） |
| POST | `/api/reload-images` | 让壁纸重读图片（`rev` 加 1） |
| POST | `/api/pick?side=` | 弹系统原生选图框，返回所选路径 |
| POST | `/api/upload?side=` | 上传一张图，压到最长边 2560px 后落盘 |
| POST | `/api/action` | `start` / `stop` / `restart` / `reset` / `reload` / `open-log` / `open-folder` / `to-tray` / `from-tray` |
| POST | `/api/quit` | 关掉面板本身 |

> `to-tray` / `from-tray` 在托盘不可用时返回 `ok:false` ＋ 一句人话说明，**不是** 500。
> 前端拿 `ok` 决定弹什么提示 —— 这是"拒绝"而不是"失败"，两者语义不同。

安全设定：只监听 `127.0.0.1`；`POST` 会校验 `Origin` 头，非本面板来源直接 `403`。

### 五条不能破的不变量

改任何一块之前先看一眼这五条 —— 它们各对应一个“看起来没坏、其实已经在骗人”的 bug：

1. **取景框的宽高比必须等于输出尺寸的宽高比。** 后端 `_preview` 最后是
   `crop(取景框).resize((vw, vh))` —— 一步硬缩。取景框比例一旦不等于 `vw:vh`，
   画面就被压扁（实测光斑拉到 1200 时压掉 4%，肉眼几乎看不出来）。
   前端 `boxOf()` 负责不把框顶出屏幕，后端负责兜底裁成同比例，**两边都要**。
   想验证就直接读响应头 `X-Box`，别自己再实现一遍后端的逻辑。
2. **配置的“读 - 改 - 写”必须在同一把锁里。** 面板是 `ThreadingHTTPServer`，
   两个 POST 真会同时跑：同时 `open('.tmp')` 在 Windows 上直接 `PermissionError`
   （界面收到 500，“拖了滑块没生效”），两个读-改-写交错则会互相吞改动。
   锁是 `_CFG_LOCK`（`RLock`），`cfg_write` 和 `apply_config` / `bump_rev` 都持它。
3. **画布上的 item：位置和像素必须一起更新，绝不能只挪位置。**
   光斑是一个**不透明**的 d×d 位图 item，内容对应"它上一次真正渲染时的那个位置"。
   只 `canvas.coords()` 把它搬到别处，画的还是旧位置的像素 —— 桌面只要露着一角，
   就会看到一块 d×d 的**错位方块**（2026-09-14 实测：462×462、填充率 0.96、
   每一行的宽度都恒等于 d。是方块不是圆），用户的原话是"光圈变方了"。
   所以**光标不在桌面上时什么都不做**（`_step` 里那段 `pause_when_covered` 分支，
   原地冻住）。原来那个 `_park()` 就是"只挪位置"的写法，已经删掉 —— 别再照着
   "省一次跨屏重绘"的思路把它加回来：省下的十几毫秒买不到这个 bug。
4. **文档不许有根级溢出；`.sw` 这种"里面藏着绝对定位元素"的容器必须自己定位。**
   开关里那个 `<input type=checkbox>` 是绝对定位的，`.sw` 当初没写
   `position: relative`，于是它的包含块一路上升到**文档** —— 绕过
   `.col{overflow-y:auto}` 和 `.layout{overflow:hidden}` 的裁剪，在视口下方顶出
   397px 隐形内容（实测：文档 1227px、视口 830px，最深的元素正是 `input`，
   `bottom=1227`）。
   后果是：**点一下开关，浏览器把刚获得焦点的 checkbox 滚进视野 → 整个界面连
   标题栏一起上窜 397px**。用户的原话是"点击冻住光斑后界面会变形"。
   最坑的是**布局一个像素都没重排**，量元素尺寸全是"没变" —— 只有量
   `documentElement.scrollHeight` 才看得见。
   两道防线：`.sw{position:relative}` ＋ 给 `input` 写死 1px 盒子（治根因），
   外加 `html, body{overflow:hidden}` 和把根滚动钉在 0 的 scroll 监听（兜底）。
   同类风险自查：全表搜 `position: absolute`，逐个确认祖先里有定位。
5. **认窗口只认 pid，不认标题；托盘图标没装上就绝不许藏窗口。**
   两条都属于“看起来很稳、实际会把人锁在外面”的那一类：
   - **标题不能用来认窗口。** Win11 给每个标签页建一个
     `Windows.Internal.Shell.TabProxyWindow`（**归 explorer.exe**，标题就是
     标签页标题），`FindWindow(None, 标题)` 有相当大概率拿到它。托盘看护拿着这个
     句柄去 `SW_HIDE`，藏掉的可能是**别人家**的窗口。判据一律走
     `current_panel_window()`：先按“我们拉起的那只浏览器 pid”找，再退回按标题找
     （`LAUNCHED_PID`，见 `launch_window`）。
     顺带一提，面板窗口归 **msedge.exe**，不归 Python 进程 —— 所以
     “本进程 pid”这个判据是找不到它的（`panel_hwnd()` 曾经就栽在这）。
   - **托盘图标不存在时，绝不把窗口藏起来。** 图标是唯一能把窗口捞回来的入口；
     没入口还藏 = 用户只剩任务管理器一条路。所以 `hide_to_tray()` 第一件事是查
     `active`，界面上那个按钮在托盘不可用时直接**停用**，`_tick()` 里还有一道
     “托盘失活就把窗口还回来”的安全闸 —— 两头都堵。
   - **退出用的是 `WM_SYSCOMMAND/SC_CLOSE`，不是 `WM_CLOSE`。** Chromium 的窗口
     过程不理会别的进程直接投过来的 `WM_CLOSE`：实测窗口纹丝不动、进程还活着、
     日志里一行都没有，托盘菜单的「退出面板」看起来就是点了没反应。
     点标题栏 × 时系统发的本来就是 `SC_CLOSE`，照抄它。（这条是
     `_probe_tray.py` 抓出来的，不是读代码读出来的 —— 静态看它“明明写了 WM_CLOSE 啊”。）

## 十一、打包成单个 exe（可选）

目标机器不想装 Python，就把它打成一个 exe：

```bash
pip install pyinstaller pillow pywin32
python build_exe.py
```

产物 `dist/SpotlightWallpaper.exe`，约 20 MB，拷给谁都能双击直接用。

`build_exe.py` 会先把三个 `.pyw` 复制成 `.py` 再交给 PyInstaller。原因：源码方式
跑时 `.pyw` 这个后缀是有意义的（双击不弹黑窗），打包时没有；而 PyInstaller 只把
`.py` 当模块找，不认 `.pyw`。复制一份镜像给它分析，主项目一个字节都不用动。

### 一个 exe，三个角色

exe 里不再有 `.pyw` 文件可以"再拉一个进程"，所以所有拉起同伴的地方都改成
**让 exe 换个角色重跑一遍自己**，靠命令行参数分（`main.py` 负责分发）：

| 命令 | 干什么 |
| --- | --- |
| `SpotlightWallpaper.exe` | 起壁纸 + 开面板 —— **双击的默认行为**，等价于 `启动聚光壁纸.bat` |
| `SpotlightWallpaper.exe --no-panel` | 只起壁纸（开机自启走这条） |
| `SpotlightWallpaper.exe --window` | 小窗口预览（安全模式） |
| `SpotlightWallpaper.exe --full` | 全屏预览 |
| `SpotlightWallpaper.exe --autostart install\|remove\|status` | 开关开机自启 |
| `SpotlightWallpaper.exe --version` | 看版本 |

所以任务管理器里同时出现几个 `SpotlightWallpaper.exe` 是**正常的** —— 壁纸一个、
面板一个，各自还带一个 PyInstaller 的引导进程。它们之间照样走单实例判重，不会重复。

### 打包后这些文件在哪

- **exe 旁边**：`wallpaper-config.json`、`wallpaper.log`、`*.pid`、`panel.ico`、
  `images/`（你自己的两张图）—— 和源码版完全一样，只是位置换成 exe 所在目录。
  单文件 exe 每次启动都会把代码解包到一个临时目录，配置写在那儿的话进程一退就
  没了，所以路径全部按"exe 在哪儿"算。
- **包内**：`panel.html`。它优先读 exe 旁边的那份（想改界面，放一份在那儿就行），
  旁边没有才用包里自带的。

### exe 用在哪、不用在哪

打包版启动要解包，头一次比源码版慢两三秒；改了代码也得重新打包（约 30 秒）。
自己在这台机器上用，源码版 + 双击 `启动聚光壁纸.bat` 更顺；exe 是给
"要发给别人 / 换台电脑不想装 Python"准备的。
